Ascend Creative Intelligence System

Una interfaz que se retira para que la campaña destaque.

Guía de diseño para una plataforma de dirección creativa con catálogos, inspectores, recursos visuales, proyectos publicitarios y generación de imágenes con IA. La experiencia debe sentirse precisa, editorial, silenciosa y contextual.

01 — Fundamentos

La campaña es protagonista; la UI, infraestructura silenciosa.

El sistema debe priorizar jerarquía, lectura y contexto. Los controles no compiten con imágenes, previews ni resultados generados.

Precisión

Alineación rigurosa, grillas previsibles, controles consistentes y estados inequívocos.

Editorial

Espacio negativo generoso, títulos con presencia y contenido visual dominante.

Contextual

Los paneles muestran solo las herramientas pertinentes al objeto seleccionado o al paso actual.

Reversible

Ediciones, filtros, selección y generación deben comunicar claramente qué cambiará y qué permanece intacto.

Principio de densidad: catálogos y tablas pueden ser compactos; editores, formularios complejos y previews deben respirar. Evitar aplicar la misma densidad a todas las vistas.

Un sistema medible antes que decorativo.

03 — Acciones & formularios

Las acciones deben tener una prioridad visual inequívoca.

Una pantalla normal debe tener una acción primaria visible. Las acciones destructivas nunca compiten visualmente con la acción principal.

Botones

Jerarquía: Primary → Secondary → Ghost → Danger. Icon-only únicamente para acciones universales y reconocibles.

Primary

Copper. Una por bloque decisional. Para crear, continuar, generar o confirmar.

Secondary

Ivory/Glass. Para guardar, editar, probar conexión o acciones alternativas.

Ghost

Acciones de baja prioridad: cancelar, cerrar, volver, limpiar.

Danger

Rojo suave, nunca relleno agresivo salvo confirmación destructiva crítica.

Inputs

Nombre interno visible en catálogo.
Usar ayuda contextual debajo; nunca como placeholder permanente para instrucciones importantes.
Focus usa Copper con halo discreto. Error debe aparecer cerca del campo, sin desplazar violentamente el layout.

05 — Paneles & vista previa

Un panel no es una card grande: tiene función, jerarquía y persistencia.

Los paneles sostienen herramientas, inspección o contexto. Su tratamiento cambia según si son primarios, secundarios, sticky o temporales.

Panel primario01

Editor de brief

Superficie sólida/Glass Strong. Contiene formularios largos y acciones persistentes.

Uso

Brand Kit, Project Editor, Recipe Editor.

Padding

20–24 px. Secciones internas separadas con línea, no con cards anidadas.

Panel secundario02

Inspector

Más ligero. Complementa una selección sin competir con la vista principal.

Uso

Detalle de catálogo, metadata, properties.

Sticky

Sí en desktop; inline debajo del contenido en tablet/mobile.

Panel de sistema03

Estado de IA

Obsidian se reserva para momentos de alto contraste: estado técnico, preview cinematográfico o navegación especial, no para todas las superficies.

Gemini connected

Reglas para Preview

Dominancia

La imagen o composición debe ocupar 65–80% del área visual del preview.

Fondo

Usar neutral cálido, checkerboard solo si transparencia es relevante, grid técnico únicamente en LayoutBuilder.

Controles

Zoom, abrir y descargar viven en overlay discreto o footer; nunca cubrir el foco visual.

Aspect ratio

Preservar siempre la proporción del formato real; evitar estirar para llenar el panel.

Reglas para Inspector

Orden

Preview → identidad → metadata → relaciones → acciones.

Anchura

300–360 px desktop. Si necesita más, deja de ser inspector y pasa a editor/panel.

Acciones

Máximo 2 visibles en footer. Resto en menú secundario.

Scroll

Scroll interno únicamente si el panel es sticky y el viewport no permite mostrarlo completo.

07 — Estados & feedback

El sistema siempre debe explicar qué está ocurriendo.

09 — Responsive & accesibilidad

Reducir complejidad, no solo columnas.

En pantallas pequeñas, transformar patrones: inspector pasa debajo, toolbar se compacta, workbench se convierte en flujo vertical.

Desktop ≥ 1180

Sidebar persistente. Catálogo + inspector. Workbench 3 zonas. Preview sticky cuando aporta contexto.

Tablet 700–1179

Sidebar overlay. Grids de 2 columnas. Inspector inline. Workbench 2 zonas con configuración debajo.

Mobile < 700

Una columna. Primary action full-width. Filtros colapsables. Tabs horizontales con scroll. Preview antes de metadata.

Focus

Todas las acciones interactivas deben tener :focus-visible perceptible.

Touch

Objetivos táctiles de al menos 40–44 px.

Contraste

Copper no debe usarse para body text pequeño sobre fondos claros si reduce contraste.

Motion

Respetar prefers-reduced-motion. Animaciones de estado no deben ser requisito para comprender el resultado.

10 — Reglas del sistema

Consistencia antes que novedad.

Estas reglas deben funcionar como contrato entre diseño y frontend.

DO

01

Usar clases y componentes canónicos por responsabilidad: catalog-card, inspector, panel, toolbar, field.

02

Usar Mesh Gradient como base ambiental y glass surfaces para legibilidad.

03

Preservar espacio negativo alrededor de imágenes, previews y resultados.

04

Diferenciar editor, inspector, catálogo y modal por función, no solo por tamaño.

05

Mostrar estados técnicos de generación con badges y queue items consistentes.

DON'T

01

No crear una variante visual nueva por cada página si el patrón ya existe.

02

No llenar todas las superficies de gradients, sombras o glass: la sofisticación depende de la moderación.

03

No convertir un inspector en un formulario completo de 500 px de ancho.

04

No usar Obsidian como superficie dominante en todo el producto; reservarlo para contraste y estados especiales.

05

No esconder información crítica solo en hover ni usar placeholders como labels.
